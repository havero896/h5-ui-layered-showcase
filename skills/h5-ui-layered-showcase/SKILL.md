# H5 UI 分层展示

把现有页面的视觉结构与使用路径整理成作品集展示画板。展示要能解释设计，同时保留原稿信息、图层可编辑性和用户已定的排版。

## 输入与边界

1. 读取当前原画板、相邻展示稿、项目说明和参考图。用户最新修改的画板优先于旧截图；参考图用于判断构图和风格，不自动提供当前项目的文案、品牌或功能。
2. 确认是否具备可编辑源画板、素材、字体和 Figma 写入能力。若只有截图或无法写入 Figma，可以先给分层方案和缺失素材清单；未经确认，不声称已做出完整可编辑成品。
3. 除非用户明确要改原稿，另建展示画板并保护原稿。比例和尺寸由用户或项目决定；不套用固定海报规格。

## 制作

1. 根据实际页面选出值得解释的层：背景与装饰、文字与导航、进度、主视觉、操作、内容卡及下一屏预告等。空泛的背景不用为了凑编号而成为核心层。
2. 从源画板复制真实文案、图层和资产，保持模块内部布局及图像比例。对可编辑的文字、形状和按钮继续使用原生节点；需要完整图像时不靠拉伸补边。
3. 依据参考图确定空间方向。若用户要求水平边与海报平行、竖边倾斜，对同一模块整体做纵向 Skew，确保背景装饰、图片、进度、按钮底和文字的透视关系一致；用户明确要求独立处理的部分单独成层。技术细节见 [Figma 实施要点](references/figma-editing.md)。
4. 按信息重要性使用玻璃、描边和高光，帮助区分层级；不要让装饰盖住标题、进度或主要操作。对原稿中被裁的完整元素、主视觉边缘或下一屏内容，按需要做不同强度的渐隐，并让同组图标和文字一起过渡。构图判断见 [视觉规则](references/visual-rules.md)。
5. 为值得解释的模块添加清楚的编号、标题和短说明。默认从“视觉表达”和“体验价值”两个角度写；若用户已有说明体系，沿用其术语。只解释画板能支持的作用，不编造业务效果或交互。引线与终点圆点要对准目标、不压文字，相关节点按模块分组。

## 验收与交付

- 并排核对原稿与展示稿：原稿无误改；文案、字体、间距、裁切范围和重要内容忠实于当前版本。
- 全局检查节奏与留白，局部放大检查倾斜错位、图像变形、玻璃边界、透明硬边、折线和圆点。检查图层仍可编辑。
- 字体在当前编辑环境缺失时，换用能加载原字体的环境完成校准；不能静默留下替代字体或轮廓化文字。
- 提供展示画板链接，说明已完成的修改与任何影响可编辑性的限制。
