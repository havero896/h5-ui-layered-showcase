# 分层展示的视觉判断

这是做作品集页面时的判断依据，不是固定模板。每次先看原页面的内容密度、主视觉形态和用户最新调整。

## 空间关系

- 一张展示画板通常包含：简短项目页眉、展示标题和一句话定位；中央有原 UI 的分层核心；左右留出标注通道；底部让下一模块或装饰自然淡出。参考图的价值是“中心聚焦、两侧解释、上实下虚”，不复制它的产品文案或配色。
- 分层要能回答“这一层负责什么”。如果纯渐变背景没有独立信息价值，可保留为未编号的氛围基底，将 01 分配给文字或导航层。
- 把同一功能单元作为一层：按钮底、图标、文字一起；进度图形与进度说明一起；主视觉与需要跟它共用透视的元素一起。是否让背景装饰、主视觉或进度倾斜，以该页面的深度关系及用户指令决定。
- 被解释的目标应在视觉上能被找到；标注越多，越需要控制左右留白、行长和互相错开的高度。

## 透视与层级

- “横向与页面平行，仅竖向倾斜”的表现，是让模块的水平边保持平行，再令竖边沿同一方向偏移。每层可以适度错开，但不要把页面内原有元素的相对排版改散。
- 玻璃层要给信息一个可感知的承托，而不抢过主视觉。上方文字与状态栏、信息卡、操作区可按需要分别设置玻璃；重要层的描边更明确，背景层更轻。用截图检查它是否真的增强层级。
- 被裁切的完整按钮可以露出画板外的轮廓，但原本不可见部分透明度要更低。主视觉边界用更柔和的浅隐；下一屏内容向下渐隐，保留“还有内容”的暗示。

## 标注写法

需要解释的小版块可采用编号、模块名和两句短说明，沿用同一版式规则；已有标注体系时以用户规范为准。

| 字段 | 解释的问题 | 示例方向 |
| --- | --- | --- |
| 视觉表达 | 画面用了什么手段形成识别与层次？ | 轻玻璃承托标题、暖色高光锁定主操作 |
| 体验价值 | 用户因此更容易理解或完成什么？ | 先读目标再选入口、看清收集进度 |

不要把“体验价值”写成未经验证的转化率、留存或效率提升。它可以谈认知顺序、选择路径和反馈清晰度，但要与画板可见内容对应。短句优先，避免行尾压到主体。

## 常见失败点

- 图像透明背景不等于放进展示稿后边界自然消失；大面积浅色素材尤其需要在实际背景上检查四边。
- 裁切按钮应检查底、图标、文字是否作为整体透明过渡。只给底板蒙版会留下漂浮的文字。
- 被倾斜的进度、主按钮和文字应沿同一空间逻辑，否则视觉上像错位。
- 折线应从标注旁留白处出发，先直线再平滑折向目标；终点圆点用标准椭圆，居中压住线端。线条和标注不能因为分组或缩放而变形。
- 不因追求“层数”加入无业务依据的装饰、任务、奖励或按钮。
- 渐隐和浅玻璃不能牺牲关键文字与主要操作的可读性；必要时缩小淡出范围，而非把核心内容一起淡掉。
